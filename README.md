# 서구STAY

### 집보다 먼저, 살고 싶은 일상을.

![운천저수지의 호수와 벚꽃, 주변 아파트 풍경](public/assets/uncheon-spring.webp)

**생활조건 선택 → 맞는 집과 동네 발견 → 확인된 거래가격 이해**

전남광주통합특별시 서구의 공동주택·학교·동네 명소를 함께 살펴보는 주거·생활 탐색 서비스다. 공원, 학교, 문화생활, 주거 면적 등 원하는 생활조건을 먼저 고르고, 그 조건에 맞는 이유와 수록된 거래 사례를 확인한다.

**제작: 전남광주통합특별시 서구 기획실 정의형**

> 이 저장소는 2026년 10월 29일 서구STAY 최신 소스를 바탕으로 만든 GitHub + Vercel 이전용 프로젝트다. 자료를 새로 수집하거나 실시간 매물 서비스로 바꾼 버전은 아니다.

## 바로 배포하기

**처음이라면 [START_HERE.md](START_HERE.md)를 순서대로 따라 한다.**

1. 이 프로젝트의 파일과 폴더를 GitHub `seogu-stay` 저장소 최상위에 올린다.
2. [Vercel 새 프로젝트](https://vercel.com/new)에서 해당 GitHub 저장소를 가져온다.
3. 아래 설정으로 배포한다. 설정값은 `vercel.json`에도 포함돼 있다.

| 항목 | 값 |
| --- | --- |
| Framework Preset | **Other** |
| Root Directory | **`./`** — `package.json`이 있는 최상위 |
| Build Command | **`npm run build`** |
| Output Directory | **`public`** |
| Install Command | **`npm ci --ignore-scripts --no-audit --no-fund`** |
| Node.js Version | **24.x** |
| 기본 기능 환경변수 | **없음** |

기본 검색·관심 저장·단지 비교·학교 안내·지도는 별도 API 키 없이 이용할 수 있다. Solar AI를 쓰려면 아래 선택 설정을 추가한다. 운영 주소는 실제 Vercel 배포가 완료된 후 발급되는 주소를 사용한다.

## 주요 기능

- **생활조건으로 탐색:** 7가지 조건 중 최대 3개를 고르고, 확인된 값으로 조건 충족 여부를 비교한다.
- **문장으로 집 찾기:** 원하는 일상을 문장으로 적는다. 기본 모드는 브라우저에서 키워드를 해석하고, Solar 연결 시 AI가 조건을 정리한다.
- **239개 공동주택 목록:** 단지명·별칭·주소·동네 검색, 24개씩 페이지 이동, 가격자료가 없는 단지도 상세·저장·비교한다.
- **생활권 지도:** 좌표가 확인된 단지, 학교와 명소를 로컬 지도 자료로 표시한다.
- **학교·학군 참고:** 52개 학교 위치, 기존 8개 단지의 지도 기준 통학구역·학교군 참고 정보를 제공한다. 실제 학교 배정을 확정하지 않는다.
- **가격 사례 읽기:** 수록된 매매 사례는 금액·전용면적·층·계약일을 함께 보여준다.
- **관심 단지·비교:** 이 브라우저에 관심 단지를 저장하고, 최대 3개 단지를 비교한다.

## 자료 수록 범위

자료 확인일은 **2026년 10월 28일**이며, 원자료별 기준일은 서로 다르다.

| 자료 | 수록량 | 해석 |
| --- | ---: | --- |
| 공동주택 목록 | **239개** | 서구청 원본 234개 + K-apt 추가 5개 |
| 지도 위치 | **53개 단지** | 나머지 단지는 주소 검색으로 확인 |
| 준공연도 | **180개 단지** | 미확인 연도는 임의로 채우지 않음 |
| 매매 사례 | **8개 단지·28건** | 현재 호가·전체 시세·전체 거래가 아님 |
| 학교 | **52곳** | 초등 29·중학교 15·고등학교 8 |
| 동네 명소 | **9곳** | 자연·문화·시장 안내 |
| 통학구역·학교군 대조 | **8개 단지** | 대표 좌표를 공식 학구도에 대조한 참고 정보 |

239개에는 아파트·주상복합·세부 유형 미확인 공동주택이 포함된다. 위치·가격 미수록은 시설이나 거래가 없다는 뜻이 아니다. 학교 거리는 직선거리이며 실제 통학 경로나 배정 결과와 다르다.

자료 출처·생활조건의 계산 기준·사진 이용조건은 [자료와 검색 기준](docs/DATA_AND_MATCHING.md)에 정리했다.

## Solar AI 연결 — 선택

Vercel 프로젝트의 **Settings → Environment Variables**에 아래 값을 등록하고 다시 배포한다. 실제 비밀값은 GitHub 파일에 넣지 않는다.

| 환경변수 | 내용 |
| --- | --- |
| `SOLAR_API_KEY` | Upstage에서 발급한 API 키 |
| `SOLAR_MODEL` | 선택. 기존 기본값은 `solar-mini4`, 지원 선택값은 `solar-mini4`·`solar-pro4` |
| `UPSTASH_REDIS_REST_URL` | AI 사용 횟수를 관리할 Redis REST URL |
| `UPSTASH_REDIS_REST_TOKEN` | 위 Redis의 REST 토큰 |

Vercel 연결에서 `KV_REST_API_URL`·`KV_REST_API_TOKEN` 이름을 제공하면 그 쌍도 사용할 수 있다. API 키와 Redis 연결이 모두 있어야 AI 준비 상태가 켜진다. 모델 이용 권한과 실제 연결 성공은 운영 환경에서 확인해야 한다.

AI는 질문을 검색조건으로 정리한다. 단지·거리·가격은 수록 자료로 계산하며, AI가 임의의 단지나 가격을 생성해 표시하는 구조가 아니다. 질문은 답변을 위해 Upstage로 전송된다. 대화는 브라우저 메모리에만 유지하고, 이 프로젝트는 질문·답변을 DB에 저장하지 않는다.

기존 Cloudflare D1의 호출수 제한을 Redis의 원자적 처리로 옮겼다. 기본 한도는 사이트 전체 하루 200회, 방문자 하루 20회·10분 5회다. 하루 경계는 UTC 기준이다. Redis가 없거나 동작하지 않으면 유료 AI 호출을 진행하지 않는다. 이 경우에도 기본 검색은 이용할 수 있다.

## 개발·검증

Node.js 24가 필요하다. 앱 실행에 별도 npm 패키지를 설치하지 않는 구성이다.

```sh
npm ci --ignore-scripts --no-audit --no-fund
npm run dev
```

표시되는 `http://localhost:3000`으로 접속한다. HTML 파일을 탐색기에서 직접 열면 JSON 자료 요청이 동작하지 않을 수 있다.

```sh
npm run build
npm test
```

`build`는 정적 파일·데이터·JavaScript와 API 진입점을 확인한다. 테스트는 AI 입력 경계, 오류 응답, 호출수 제한과 기존 조건 비교의 일치를 확인한다. 모의 API 테스트 통과가 실제 Solar·Redis 연결 성공을 뜻하지는 않는다.

## 이전 시 알아둘 점

- 기존 사이트의 주소와 새 Vercel 주소가 다르므로, 브라우저에 저장한 관심 단지는 자동으로 이동하지 않는다.
- 원래 수록된 단지 ID와 JSON 데이터는 유지한다. 기존 위치·가격 미확인 항목도 그대로 남긴다.
- 이 저장소는 정적 화면 + Vercel Node.js Functions 구성이다. Next.js·Cloudflare Worker 배포 설정을 선택하지 않는다.
- 현재 화면 이동은 해시 링크를 사용한다. 모든 경로를 `index.html`로 보내는 rewrite를 추가하면 API나 데이터 요청이 깨질 수 있다.
- 원자료 자동 수집·실시간 가격 갱신·전세·월세·회원 계정 동기화는 구현 범위에 포함되지 않는다.
